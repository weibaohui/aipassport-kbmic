# Assets

## Fonts

| File | Spec | Purpose and origin |
| --- | --- | --- |
| [`fonts/kbmic_charset.txt`](fonts/kbmic_charset.txt) | plain text, 3616 code points | The complete `--symbols` input for `lv_font_conv`: 95 printable ASCII + 21 full-width/UI symbols + the 3500 level-1 characters from the Chinese national standard character set. **Generated by `tools/gen_font_charset.py`**, never hand-maintained. |
| [`fonts/common_3500.txt`](fonts/common_3500.txt) | plain text, 3500 characters | Level-1 table of the standard Chinese character set. From [shengdoushi/common-standard-chinese-characters-table](https://github.com/shengdoushi/common-standard-chinese-characters-table), file `level-1.txt`. |
| [`fonts/NotoSansSC-Regular.otf`](fonts/NotoSansSC-Regular.otf) | 7.9 MB | Source typeface, SIL OFL 1.1. Full licence text in [`OFL.txt`](fonts/OFL.txt). |
| [`fonts/app_font_16.c`](fonts/app_font_16.c) | 16 px / 4 bpp / LVGL C source | The single UI font, compiled into the `main` component. **~3.0 MB of source, ~450 KB of Flash.** |

### Why the whole 3500-character set

Users can create their own keyboard modes over MCP and give them names in Chinese. Those names appear at **runtime**, so scanning the source for them does not work. Rather than guess which names people will pick, the whole level-1 table is compiled in: it costs about 450 KB of Flash (the partition still has 76% free) and in exchange any ordinary Chinese name renders correctly.

There is only one UI font. Title, home screen, settings menu, mode list, key editor, and action picker all share it.

### Regenerating

```bash
# 1) rebuild the symbol table (needed when the punctuation set or the character table changes)
python3 tools/gen_font_charset.py

# 2) regenerate the font (tool version pinned to 1.5.3)
npx lv_font_conv@1.5.3 \
  --font assets/fonts/NotoSansSC-Regular.otf \
  --size 16 --bpp 4 --format lvgl --no-compress \
  --lv-font-name app_font_16 --lv-include lvgl.h \
  --symbols "$(cat assets/fonts/kbmic_charset.txt)" \
  --output assets/fonts/app_font_16.c
```

The source typeface and the character table are both committed (following the `aipassport-glm` asset convention), so this works offline.

### Glyph coverage gate

`tests/test_ui_charset.py` runs in the host gate and checks that **every non-ASCII character in `main/kbmic_ui.c` string literals is present in `kbmic_charset.txt`**.

Note that it checks more than Han characters: full-width colons and the interface's own `▸` cursor glyph are just as capable of being missing, and the consequence is identical. Change the UI copy without regenerating the font and the gate fails.

### Why not LVGL's built-in CJK font

LVGL ships `LV_FONT_SOURCE_HAN_SANS_SC_14/16_CJK`, roughly 1.0/1.2 MB each, but their glyph sets are a **random sample of 1373 characters** — in testing they were missing 15 characters this interface needs on the first screen. Enabling one costs 1 MB and still renders wrong, and it would not cover user-chosen mode names either.
